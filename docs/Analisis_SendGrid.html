📧 Análisis SendGrid

Propuesta de Mejora del Sistema de Correos

Proyecto: URBONT API Versión: 1.2.2 Fecha: Septiembre 2026 Estado: Viable

📋 Resumen Ejecutivo

Propuesta: Consolidar el sistema de envío de correos usando SendGrid como proveedor único.

Beneficios principales:

  • Un proveedor: Simplificar mantenimiento (hoy: Resend + SMTP)
  • Mejor deliverability: 99% inbox vs 70% SMTP genérico
  • Gratis: 100K emails/mes sin costo (URBONT usa ~1K/mes)
  • Webhooks: Tracking de aperturas, clics, bounces
  • Profesional: Templates, analytics, IP dedicada

Tiempo de implementación: 3-4 horas

📨 Tipos de Correos que Existen Actualmente

1️⃣ Recibo de Viaje (Trip Receipt)
  • Cuándo: Al completar un viaje
  • Para: Pasajero
  • Proveedor actual: ✓ Resend
  • Contenido: Detalles del viaje, conductor, vehículo, tarifa desglosada, ID
  • Volumen estimado: ~100/mes
  • Archivo: server/services/email.ts:123
2️⃣ Notificación de Soporte (Support Ticket)
  • Cuándo: Usuario abre un ticket de soporte
  • Para: Administrador
  • Proveedor actual: ⚠ SMTP genérico
  • Contenido: Categoría, prioridad, descripción, datos del usuario, ID ticket
  • Categorías: Lost Item, Driver Issue, Billing, App Issue, Safety, Other
  • Volumen estimado: ~20/mes
  • Archivo: server/api/support.ts:30-104
3️⃣ Código OTP (One-Time Password)
  • Cuándo: Usuario solicita verificación para login
  • Para: Usuario (pasajero/conductor)
  • Proveedor actual: ⚠ SMTP genérico
  • Contenido: Código de 6 dígitos, instrucciones, expiración (10 min)
  • Volumen estimado: ~500/mes (múltiples intentos por usuario)
  • Archivo: server/api/auth/otp.ts:140-160

🔴 Problemas Actuales

  1. SMTP genérico no confiable: Gmail/otros tienen rate limits, spam folder frecuente
  2. Dos proveedores: Complejidad innecesaria, dos secretos API, dos dashboards
  3. Sin tracking: No sé si los correos se abrieron o si llegaron al spam
  4. Sin garantía SLA: SMTP genérico sin SLA de disponibilidad
  5. Escalabilidad limitada: SMTP genérico falla si envías >100 emails/hora
  6. OTP en memoria: Si el servidor reinicia, se pierden los códigos
  7. Sin IP dedicada: Comparte IP con otros, mala reputación colateral

🛠️ Cómo Implementar SendGrid

Fase 1: Setup en SendGrid (30 minutos)

  1. Ir a sendgrid.com → Sign up (gratis)
  2. Verificar dominio (agregar registros DKIM/SPF en tu DNS)
  3. Crear API Key (Settings → API Keys → Create)
  4. Copiar la clave

Fase 2: Configurar Variables (.env)

SENDGRID_API_KEY=SG.xxxxxxxxxxxxxxxxxxxxx SENDGRID_FROM_EMAIL=noreply@urbont.com SENDGRID_FROM_NAME=URBONT

Fase 3: Instalar Librería

npm install @sendgrid/mail

Fase 4: Crear Servicio Unificado

Archivo nuevo: server/services/sendgrid.ts

import sgMail from '@sendgrid/mail'; import { logger } from '../lib/logger'; const SENDGRID_KEY = process.env.SENDGRID_API_KEY || ''; if (SENDGRID_KEY) sgMail.setApiKey(SENDGRID_KEY); export async function sendEmail(options: { to: string; subject: string; html: string; category?: string; customArgs?: Record<string, string>; }): Promise<boolean> { if (!SENDGRID_KEY) { logger.warn('[EMAIL] SENDGRID_API_KEY not set'); return false; } try { await sgMail.send({ from: { email: process.env.SENDGRID_FROM_EMAIL, name: process.env.SENDGRID_FROM_NAME }, to: options.to, subject: options.subject, html: options.html, categories: options.category ? [options.category] : [], customArgs: options.customArgs, }); logger.info(`[EMAIL] Sent to ${options.to}`); return true; } catch (err: any) { logger.error(`[EMAIL] Failed: ${err.message}`); return false; } }

⚠️ Riesgos Identificados

  1. Dominio no verificado: SendGrid rechaza envíos sin DKIM/SPF. Solución: Verificar en setup inicial (~30 min)
  2. Rate limits: SendGrid tiene límites según plan. Para URBONT: ilimitado (plan gratis)
  3. Cambio de proveedor futuro: Si SendGrid falla, migrar a otro toma ~2-3 horas. Mitigation: Abstraer con servicio
  4. API Key expuesta: Si alguien accede, pueden enviar correos fake. Solución: Mantener en .env (nunca en git)
  5. Spam en dominio: Si mandas spam, SendGrid puede desactivar cuenta. Solución: Validar emails antes de enviar
